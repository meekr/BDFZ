## 二、图纸实测结论

### 2.1 图纸之间的关系

| 关系 | 方法 | 结果 |
|---|---|---|
| 02 ↔ 03 | 边缘图 ECC 仿射配准 | 几乎重合：缩放 1.0007 / 1.0035，平移 < 3 px |
| 01 → 02 | 建筑粗轮廓 ICP + 相似变换 | 缩放 0.9857，旋转 −0.02°，平移 (12.8, 87.9) px；87% 轮廓点误差 < 3 px |
| 04 → 02 | 学术中心剪影匹配 | 缩放 0.4608，**旋转 35.8°**，IoU 0.91 |
| 05 | 剖面 | 学术中心南北向剖切：左端南侧，右端北侧主入口 |

01、02、03 可合并为同一个"总平面坐标系"；04 需先旋转 35.8° 再缩放并入。

### 2.2 比例尺

- 04 的比例尺可靠：刻度 0 / 5 / 10 / 20 / 50 m 位于 x = 1481.5 / 1515 / 1550 / 1618.5 / 1823 px，**6.83 px/m**。
- 换算到 02/03（2000 px 版）：6.83 × 0.4608 = **3.147 px/m**（1 px ≈ 0.32 m）。
- 独立复核：OSM 学术中心外轮廓面积 17,307 m²，对应 02 上 3.10 px/m，相差 1.5%。
- 02、03 自带的比例尺太小，刻度检测不稳定，不用于定标。
- 高清版 03（9921 px）约 15.6 px/m，描图精度可达 0.3 m 以内。

### 2.3 朝向

- 01–03 图面上方与正北相差约 1° 以内（跑道倾角：线稿约 20°，卫星约 21°）。
- 02、03、04 上的指北针符号是倾斜的，与实地不符，**不作为朝向依据**，直接采用图面方向。

## 三、现状基线（Vite 版，提交 `d2f2c05`）

测量方法：构建 `dist/index.html`，在浏览器中把各建筑组的网格投影到地面得到剪影；按模型自带叠图的摆放方式换算到 02 图坐标；与 02 上提取的建筑粗轮廓比较。这是临时方法，误差约 1–2%，P0 会把它正式化为 `npm run check:align`。

### 3.1 叠图本身的摆放错误

- 叠图平面为 `SITE` 498 × 270 m（`src/main.js:29`、`1083`），叠图图片 1800 × 1000 px，**横纵比例不一致**。
- 换算到 02 坐标后为 3.364 px/m（横向）和 3.447 px/m（纵向），正确值 3.147 px/m。叠图**横向小 6.5%、纵向小 8.7%**，并且被拉伸变形约 2.5%。
- 正确的叠图平面为 **532.4 × 295.8 m**（等比例）。最终数值由配准确定。
- 打开叠图时看到的错位，一部分来自叠图本身，与建筑无关。
- 三层平面叠图 160 × 160 m（`src/main.js:1089`），尺寸基本正确（按比例尺应为 159–161 m）。旋转用 `MAIN_ANGLE`（`src/main.js:1092`），需按 04 → 02 的 35.8° 复核。
- 02 屋顶平面、05 剖面目前没有内嵌。

### 3.2 建筑与 02 的偏差

| 建筑 | 叠图下 IoU | 中心偏差 | 需要再转 | 只看形状的 IoU | 面积（模型 / 图纸） |
|---|---|---|---|---|---|
| 学术中心 | 0.61 | 21.4 m | −15.9° | 0.87 | 18,154 / 16,929 m² |
| 体育及艺术中心 | 0.02 | 105.2 m | −14.4° | 0.47 | 10,001 / 11,634 m² |
| 宿舍综合楼 | 0.22 | 42.6 m | −25.7° | 0.82 | 15,766 / 16,909 m² |

"只看形状的 IoU"是把模型剪影按 3.147 px/m、自由平移和旋转后的最好结果，用来区分"摆错了"和"形状错了"。学术中心和宿舍主要是位置和朝向错；体育及艺术中心形状也错。

### 3.3 田径场

- 模型跑道剪影中心 (−146.7, −51.7) m，外包 106.9 × 180.5 m。
- **跑道长轴方向错了约 48°**：模型长轴为东偏南约 21°（近东西向），图纸和卫星为北偏西约 20°（近南北向）。

### 3.4 原因

1. **几何来源错**：`src/data/campus_geo.json` 来自 OSM 和卫星，不是图纸。OSM 精度 ±5–10 m，而且与图纸本身有差异。
2. **学术中心旋转了两次**：`cloud_outer` / `cloud_inner` 已经是世界坐标，`cloudShape()` 又把它放进旋转了 `MAIN_ANGLE` 的 `cloudRoot`（`src/main.js:852`、`860-862`）。
3. **跑道方向用错**：跑道直道沿局部 X 轴，再旋转 `MAIN_ANGLE` −21.2°（`src/main.js:612`、`621-627`），结果长轴接近东西向。轴向 159° 指的是长轴近南北。
4. **体育及艺术中心仍是手写坐标**：转角点 (−188.7, 119.3) 和 L 形顶点写在代码里（`src/main.js:721`、`731-733`），南臂伸出方向与 02 不符。
5. **宿舍中心和旋转角手写**：`DM = [138.4, -34.1]`、−12.8°（`src/main.js:948-952`）。
6. **说明文字与基准不符**：文件头和资料来源弹窗写的是"以 OSM 与 Esri 卫星校准"（`src/main.js:6`、`1284`、`1299`）。

## 五、对齐方法

### 5.1 统一坐标系

- 模型世界坐标 = 02 图面坐标按 3.147 px/m（P0 定稿）换算为米。
- X 向东（图面向右），Z 向南（图面向下），Y 向上，原点取用地中心（P0 用 03 的用地红线确定）。
- 01、03 按 2.1 的变换并入；04 先旋转 35.8° 再缩放并入；05 按剖切线放到对应位置。

### 5.2 描图流程

1. `scripts/register.py`：5 张高清图相互配准，输出 `src/data/frames.json`。
2. `scripts/trace.py`：在高清版 02 上提取建筑粗轮廓 → 闭合 → 简化（容差 0.2 m）→ 圆角段拟合圆弧 → `src/data/buildings/*.json`。
3. 人工校正：简单描图页（`scripts/trace.html`），叠放高清图纸，可拖动顶点、增删圆弧，导出 JSON。
4. 高度数据：从 05（辅以 06、07）读取标高，写入 `levels` 字段。

### 5.3 内嵌叠图

- 01、03、04 叠图改为按 `frames.json` 的变换摆放，等比例，不再铺满 `SITE`。
- 新增 02 屋顶平面叠图（放在屋面高度）和 05 剖面叠图（竖直放在剖切线上）。
- 叠图打开后与模型目视无错位，是最直接的验收方式。
- 内嵌图纸保留"图纸 © Crossboundaries"署名。

### 5.4 验收指标

| 检查 | 方法 | 通过标准 |
|---|---|---|
| 平面轮廓 | 正交顶视（3.147 px/m），建筑剪影与 02 粗轮廓比较 | 中位偏差 ≤ 0.5 m，最大偏差 ≤ 1.5 m，IoU ≥ 0.97 |
| 首层与场地 | 同上，对照 03 的跑道、球场、道路、庭院线 | 中位偏差 ≤ 0.5 m |
| 学术中心三层 | 3F 高度水平剖切，对照 04（变换后） | 外环与内院中位偏差 ≤ 0.5 m |
| 剖面 | 沿 05 剖切线正交侧视，对照楼板线和地形线 | 标高偏差 ≤ 0.3 m |
| 叠图 | 01/02/03/04/05 叠图逐一打开 | 目视无可见错位 |

结果写入 `reports/align/`（偏差表 + 叠图截图）。第三节的基线数字作为起点。
