# 北大附中海口学校 3D 模型 · Blender MCP 开发计划

版本：v1（2026-11-16）　工具：Blender 5.3 + MCP for Blender（协议 16）+ Droid

## 一、目标与原则

**目标**：在 Blender 中从零构建北京大学附属中学海口学校（Crossboundaries 设计，2024 建成）的整体校园模型：场地、道路与台地、田径场、学术中心、宿舍综合楼、体育及艺术中心、图书馆、行政楼、技术中心、实验室、景观。最终效果必须与设计图纸和实景照片对得上。

**原则**

1. **只信 A 级资料**：几何来自 `refs/drawings/2024_built*`；立面、材质和建成状态来自 `refs/photos/2024_built_yubai`。级别定义见 `refs/README.md`。
2. **旧数据只当线索**：`legacy_unverified/` 里的数值必须在 A 级图纸上重新量取，才能进入新模型。
3. **图纸与照片冲突时**：平面尺寸、标高以图纸为准；建成后可见的形态（层数、立面分格、构件有无）以照片为准。每处冲突都写进 `docs/差异记录.md`，写明证据。
4. **数据与建模分开**：所有量取结果写进 `data/*.json`，Blender 只读数据建模。改数据后重建，不在 Blender 里手调坐标。
5. **每个阶段有验收门槛**，未达标的如实记录，不掩盖。

## 二、坐标与单位约定

| 项 | 约定 |
|---|---|
| 单位 | 米，Blender Unit Scale = 1.0 |
| 轴向 | +X 东，+Y 北，+Z 上 |
| 原点 | 学术中心中央庭院地面，01 图标注 `43.00 (±0.00)` → Z = 0 |
| 平面北向 | 先假定图面上方即北（旧项目结论，**P0 用航拍照片与跑道朝向复核**） |
| 标高 | 统一换算到 ±0.00 = 绝对 43.00 |

## 三、项目结构

```
BDFZ_V3/
├── refs/                 A–C 级参考资料（只读）
├── legacy_unverified/    D 级旧产物（只读，可能有错）
├── data/                 新量取的数据（JSON，每个值带来源图号与像素坐标）
├── tools/                Python 量取脚本（OpenCV/numpy，在 Blender 外运行）
├── blender/
│   ├── bdfz.blend        主文件
│   └── build/            bpy 建模模块，按建筑分文件；通过 execute_blender_code 执行
├── checks/               校正产物：叠图、相机匹配对比图、偏差报告
└── docs/                 开发计划、差异记录、阶段记录
```

bpy 代码保存在 `blender/build/*.py`，通过 MCP 的 `execute_blender_code` 发送执行，保证模型可以从数据完全重建。每段代码控制在小批量内，避免超时；每个阶段结束保存 `.blend` 并另存一份带日期的备份。

## 四、Blender MCP 的用法

| 工具 | 在本项目中的用途 |
|---|---|
| `execute_blender_code` | 建模、导入参考图、设置相机与材质、批量重建 |
| `get_scene_info` | 核对对象清单、尺寸、位置、层级 |
| `look`（`camera`/`angles`/`viewport`，`solid`/`wireframe`/`xray`/`rendered`） | 每步完成后自查：正交顶视对 02 平面、正交侧视对 05 剖面、透视相机对照片 |
| `search_assets` / `import_asset`（Poly Haven） | 只用于 HDRI、通用材质贴图、树木等配景；需要在 Blender 侧栏勾选 Poly Haven |
| `generate_3d` | 不用于建筑本体（无法保证尺寸），最多用于零散小品 |

校正手段：

- **平面叠图**：把高清图纸按标定比例铺成参考平面（Image Empty 或带贴图的 Plane），正交顶视下用 `look` 对比轮廓。
- **剖面叠图**：05/06/07 剖面竖直立在剖切线上，正交侧视对比楼层线与屋面。
- **照片相机匹配**：照片设为相机背景，按照片中可识别的点（建筑转角、跑道、道路）求相机位置、朝向与焦距（Blender 内手动对位或 fSpy 求解后导入），再用 `look(camera)` 半透明叠加对比轮廓。

## 五、分阶段计划

### P0 基准与标定

1. 建立 Blender 场景：单位、集合（`REF_Drawings`、`REF_Cameras`、`Site`、`Bldg_*`、`Landscape`）。
2. 在高清图上重新量取比例，至少三条互相独立的证据：
   - 04 图 50 m 比例尺；
   - 03 图 400 m 标准跑道（直道 84.39 m、弯道半径 36.5 m、道宽 1.22 m）；
   - 航拍照片中已知尺寸物（标准球场 28×15 m、泳池 50 m）。
3. 求 01 / 02 / 03 / 04 之间的配准（旧值只作初值），记录残差。
4. 复核北向：跑道长轴方向、道路方向与航拍照片 wx_03、wx_36 对照。
5. 从 05 剖面两点标定竖向比例，读出全部楼层与屋面标高，与 01 上的层数标注（学术中心 4F/5F、宿舍 5F、体育 2F 等）互相核对。
6. 产物：`data/frames.json`、`data/levels.json`、`checks/p0_*.png`。

**门槛**：三种比例证据相互偏差 ≤ 1%；01/02/03 叠合后建筑轮廓偏差中位 ≤ 0.5 m；标高读数与 01 层数标注无矛盾。

### P1 场地

1. 用地红线、外围市政道路（含东侧市政路）、校内道路与 6 个出入口（03 + 01 标注）。
2. 地形台地：北入口广场 −5.00、南侧草地 −3.00、南台地 +5.00、庭院 ±0.00、抬高操场 +6.00 等，按 01/03/05 建分级平台与坡道、台阶。
3. 400 m 田径场（抬高平台，下方车库）、看台、5 块斜向小球场、3 片标准球场。
4. 产物：`blender/build/site.py`、`data/site.json`。

**门槛**：正交顶视对 03 线稿，道路与场地边缘偏差中位 ≤ 0.5 m、最大 ≤ 1.5 m；跑道尺寸符合 400 m 标准。

### P2 主体体量（逐栋）

顺序按复杂度与可信资料多少排列：

| 顺序 | 建筑 | 主要依据 | 照片校正 |
|---|---|---|---|
| 1 | 学术中心（星形庭院环楼、X 形连廊、底层架空） | 02 外轮廓与洞口、04 三层平面、05 剖面、14 轴测 | wx_01、02、09、10、14、18、23 |
| 2 | 宿舍综合楼（16 个小庭院阵列） | 02、08 单元平面、09–12 单元轴测、13 轴测 | wx_08、11、31、33、34 |
| 3 | 体育及艺术中心（L 形，弧形屋面，泳池/篮球馆/剧场） | 02、03 首层、07 长剖面 | wx_35、04、01 |
| 4 | 图书馆、行政、技术中心、实验室 | 01、02、03 | wx_01、03、08 |

每栋：从高清 02 屋顶平面描外轮廓与庭院洞口 → 拉伸到 05/06/07 读出的楼层 → 楼板分层。

**门槛**：每栋正交顶视剪影对 02，IoU ≥ 0.97、偏差中位 ≤ 0.5 m、最大 ≤ 1.5 m（出挑构件单独统计）。

### P3 竖向与结构

1. 楼层板、层高、屋面与女儿墙（05、06、07 剖面）。
2. 学术中心底层白色 V/斜柱：数量、位置、倾角从 2024 照片（wx_09、14、18）和 2020 施工照片计数与量取，不用旧项目的 ±12° 示意值。
3. 屋面钢格栅/遮阳构架、天窗、连廊与坡道。

**门槛**：正交侧视对 05 剖面，楼层线偏差 ≤ 0.3 m；斜柱数量与照片一致。

### P4 立面

1. 学术中心：深灰水平带 + 通长玻璃带窗、圆角转角（wx_10、16、19）。
2. 宿舍：白色立面、走廊栏板、竖向分格（wx_11、27、33）。
3. 体育及艺术中心：大跨弧形屋面与立面。
4. 立面分格从照片相机匹配后反投影量取，与 08–14 图纸核对。

**门槛**：每个立面至少一张照片相机匹配，窗带层数、分格节奏、转角形态与照片一致。

### P5 景观与材质

1. 庭院绿化、铺装、草坡、棕榈与乔木（Poly Haven 资产或简化程序化树）。
2. 材质：深灰金属板、白色涂料、玻璃、混凝土、塑胶跑道、人造草。
3. 海口低纬度天空 HDRI 与日光。

### P6 照片校正（总验收）

1. 选 8–10 张覆盖全园的 2024 照片：航拍 wx_01、03、08、23、35；人视 wx_09、14、15、18、33。
2. 每张建一台匹配相机（`REF_Cameras` 集合，相机参数写入 `data/cameras.json`）。
3. 渲染并与照片半透明叠加，生成 `checks/photo_match_*.png`。
4. 逐张记录不一致：位置偏移、体量缺失、层数、立面差异。修正数据后重建，直到通过。

**门槛**：航拍匹配中，主要建筑转角与照片位置偏差 ≤ 照片宽度的 0.5%；没有可见的体量缺失或多余；人视照片中层数、窗带、柱子数量一致。

### P7 交付

- `bdfz.blend`（干净的集合结构，参考图集合可隐藏）；
- 导出 `glb`；
- 标准渲染：鸟瞰、星形庭院、主入口、宿舍庭院、体育中心各一张；
- `checks/` 下的全部校正对比图与偏差报告。

## 六、每步的工作循环

```
量取（tools/，写 data/*.json，带来源）
  → 建模（blender/build/*.py，经 execute_blender_code）
  → 自查（look：顶视/剖面/相机匹配，get_scene_info 核对尺寸）
  → 对照 A 级图纸与照片
  → 有偏差：改数据或算法，重建；有冲突：写 docs/差异记录.md
  → 达标：保存 .blend，更新阶段记录
```

## 七、风险

| 风险 | 应对 |
|---|---|
| 图纸比例尺不自洽、配准角度不确定 | P0 用三条独立证据交叉定标，不用单一比例尺 |
| 图纸为方案/扩初深度，与建成状态不同 | 照片决定建成形态，差异记录在案 |
| 没有场馆内部详图 | 室内只做到大厅级别，标为推断 |
| `execute_blender_code` 执行大段代码超时或卡住 Blender | 分批执行，几何生成用 bmesh，每阶段保存 |
| 旧数据错误被带入 | 只从 A 级资料重新量取；必须引用旧值时在数据里标 `"verified": false` |
| 照片有广角畸变 | 相机匹配时只用画面中部的点，或先做镜头校正 |

## 八、待确认事项

- 是否需要室内（泳池、篮球馆、剧场、图书馆）；目前计划只做外部，室内到大厅级别。
- 交付格式：只要 `.blend` 与渲染图，还是也要 `glb`/网页漫游。
- 建模精细度：建议外部达到"立面分格级"（LOD 300 左右），不做家具。
